# Копейка 3 / Финна

Личные финансы: смены, касса с переносом, резервы, долги, облако.

## Логика кассы
- **Касса** = начальный остаток + доходы − расходы − депозиты в резервы + выводы
- Остаток **не обнуляется** в новом месяце — переносится
- Долги влияют на «Доступно», не на кассу
- Погашение долга — отдельный расход
- Удалённые операции, долги, резервы и платежи не входят в расчёт
- Якорь месяца (`settings.month`) меняется только при переносе кассы, не при добавлении операции
- Удаление резерва **возвращает накопленное в кассу** (вывод), история операций сохраняется
- Если часы устройства ушли назад, openingBalance не пересчитывается
- Голосовой помощник и сброс оплаты тоже **мягко удаляют** записи — операции резерва не вырезаются
- В день зарплаты лимит считается на новый период (сегодня → день перед следующей зарплатой), а не «1 день»

## Нужные траты
- Лимит категории на период задаётся вручную и **не растёт** от экономии
- При закрытии периода (1-е число или день зарплаты) неиспользованный остаток лимита идёт в **накопления** — это учёт экономии, не новый лимит
- Повторное закрытие того же периода не начисляет накопления дважды
- Накопления **не обнуляются** при смене периода и сразу пишутся в снимок кассы
- Если приложение не открывали несколько циклов, пропущенные периоды закрываются по очереди — экономия не теряется

## Сохранность данных
- Локальное состояние шифруется (AES-GCM)
- Пока расшифровка не завершена, облако **не пишет** поверх кассы
- Если расшифровка не удалась — зашифрованный снимок не перезаписывается пустым состоянием
- При сбое ключа касса **восстанавливается** из Загрузки/Finna, локальных слотов или облака (явное восстановление снимает блокировку)
- Импорт JSON работает даже если локальный снимок не открылся
- 5 локальных снимков + файлы в Загрузки/Finna
- Облако не затирает живые данные пустым снимком
- Облако не помечает строку удалённой, если она просто ещё не доехала до другой копии
- Выход из облака не удаляет кассу на устройстве
- Облако не затирает лимиты и накопления, даже если операций ещё нет
- На двух устройствах накопления разных периодов **складываются**, а не затирают друг друга
- Автообновление APK **обязательно** проверяет SHA-256
- После перезагрузки телефона проверка обновлений ставится снова (включая Realme/Xiaomi)
- Фоновая проверка `update.json` не кэшируется и ставится точным будильником
- Веб-сборка больше не грузит `app.js` с CDN — в репозитории лежит полный файл
- Рацион Магнит считает дробные граммовки (0.15 кг больше не обнуляется)
- Кнопка рациона есть на главном экране и в веб-версии
- Снимок последней синхронизации облака шифруется так же, как касса
- Аварийная копия кассы больше не подменяется снимком облака
- Пока облако пишет, новая операция на телефоне не затирается
- В коротком месяце (февраль) день зарплаты 31-го считается последним числом
- Параллельные сохранения кассы: побеждает последний снимок, старый не затирает новый
- При переполнении хранилища сначала чистятся старые слоты — живая касса пишется в приоритете
- Новый ключ шифрования не создаётся, если на устройстве уже есть зашифрованный снимок
- Слияние облака пересчитывает якорь месяца: доход в уже закрытом месяце с другого телефона не пропадает
- Рацион Магнит входит в JSON-копию и поднимается вместе с кассой
- Импорт JSON не затирает рацион, пока не подтвердишь замену
- Если живая касса не записалась, более новый аварийный слот поднимается при старте
- Ключ шифрования дублируется (второй слот + нативное хранилище Android)
- Автообновление ставит APK только с GitHub-релиза Финны и только с валидным SHA-256
- Виджет считает выводы резерва так же, как касса (не любой «не депозит»)
- Битый живой снимок больше не затирает аварийную копию — при сбое расшифровки касса поднимается из неё
- Аварийный слот не откатывает живую кассу из‑за удалённых строк
- Импорт пустого JSON не затирает кассу
- Перебор файлов в Загрузки/Finna не подменяет рацион, пока не выбран снимок
- Лимит категории при облаке не подскакивает от старого значения на другом телефоне
- Редирект автообновления только на github.com / githubusercontent.com
- Удаление последней операции не считается «пустой кассой» — снимок пишется, облако не возвращает старое
- Аварийные слоты в памяти телефона шифруются так же, как касса (файлы в Загрузки/Finna остаются читаемыми для восстановления)
- Аварийный слот выбирается **по времени**, не по числу живых строк — удаление всех операций не откатывается старой копией
- Tombstone в облаке держится, даже если строка уже убрана из массива
- Более новый аварийный слот поднимает кассу даже если в нём меньше живых строк (удаления после сбоя записи)
- Рацион Магнит едет в облако вместе с кассой (побеждает более новый)
- Автообновление снова предлагает APK, если скачивание не удалось
- Ключ шифрования не создаётся случайным, если его не удалось сохранить — касса открывается после перезапуска
- Копии в Загрузки/Finna перезаписываются, а не плодят дубли
- Сворачивание приложения сразу дописывает кассу
- Уведомление об обновлении сразу открывает установку
- Аварийное восстановление сравнивает **время снимка**, а не строки: файл `finna-day-2026-10-01` не проигрывает более старому `finna-latest` с ISO-датой сентября
- Сворачивание приложения сразу пишет аварийный слот, шифрование догоняет — снимок не теряется, если AES не успел
- Фоновый пуш обновления не помечает версию, пока уведомление реально не показано
- PWA кэш совпадает с версиями скриптов, включая `profile.js`
- Android Auto Backup выключен — касса не уезжает в Google без ключа шифрования

- Сворачивание пишет аварийный слот сразу, даже если обычное сохранение было меньше 8 секунд назад — но только если касса реально изменилась
- Дневной файл в Загрузки/Finna перезаписывается при изменении кассы, а не один раз утром
- Проверка обновления в веб-версии не сообщает о «новой версии», если на странице нет Android-кода

- Правка операции в уже закрытом месяце двигает кассу: удаление старого расхода возвращает деньги, запись задним числом списывает
- Новый долг с пометкой «уже погашено» не создаёт повторный расход и не занижает кассу
- Голос меняет и удаляет последнюю операцию по времени, а не случайную строку в конце списка

- Правка или удаление платежа по долгу двигает «уже погашено» вместе с кассой — «Доступно» не раздувается
- Сброс обязательного платежа возвращает расход в кассу, даже если его дата не совпала с месяцем на экране
- План дня не даёт заплатить по долгу больше остатка и связывает расход с долгом
- Голос удаляет последний доход и расход по времени операции, а не по концу списка

- План дня связывает платёж только с долгом с тем же именем и не переплачивает остаток
- Правка расхода по долгу не поднимает «погашено» выше суммы долга и не съедает уже погашенное без кассы
- Сброс или правка обязательного платежа одного месяца не трогает оплату другого месяца

- Правка «уже погашено» у долга не создаёт доход и не списывает кассу: это история до учёта. Кнопка «Платёж» по-прежнему пишет расход
- Если новое «уже погашено» меньше уже проведённых платежей, лишние расходы снимаются и деньги возвращаются в кассу — фантомный доход не появляется
- Платёж по долгу с датой в будущем месяце не уменьшает остаток долга и «Доступно» в текущем месяце
- План дня не создаёт новый долг, если имя не совпало со списком

- Правка «уже погашено» смотрит на сумму к месяцу на экране и не трогает будущий платёж: сохранение формы больше не занижает остаток долга
- Платёж по долгу не превышает остаток с учётом уже запланированного будущего платежа
- Голос платит и удаляет долг только при точном имени, а не по куску фразы
- Оплата обязательства учитывается и если в копии месяц записан вместе с датой
- Сброс оплаты обязательства находит её и по дате, если поле месяца пустое — касса и «оплачено» снова совпадают

- Правка расхода с комментарием магазина не подменяет категорию бюджета этим комментарием. Категория меняется, только если ввести имя из списка
- План дня записывает покупку в категорию бюджета (продукты, транспорт и т.д.), а не в свободный текст
- Платёж по долгу, привязанный только именем, получает постоянную связь: следующее переименование долга его не теряет
- На двух телефонах разные платежи по одному долгу **складываются** в «уже погашено», а не остаётся сумма только одного телефона
- Пополнения одного резерва с двух телефонов складываются в накопленное. Касса по-прежнему уменьшается на каждую операцию
- «Уже накоплено» при создании резерва — история до кассы: деньги не списываются, пока не нажать «Пополнить»
- Правка «уже накоплено» не придумывает доход. В кассу возвращается только сумма, которая раньше ушла туда пополнением
- Удаление резерва возвращает в кассу только проведённые пополнения, а не всю историю накоплений
- «Снять» тоже возвращает в кассу только пополнения из неё. Накопленное до учёта кассы уменьшает резерв, но не увеличивает кошелёк
- Правка или удаление операции резерва в списке пересчитывает и кассу, и накопленное. Удаление пополнения не оставляет «снятие» без денег — лишнее снятие тоже снимается
- Снятие в списке операций показывается как возврат в кассу, а не как расход
- Прогноз темпа не считает долги и обязательные платежи ежедневной тратой
- Голос и рацион кладут кафе в продукты, проезд в транспорт, сигареты в карманные — лимит категории их видит
- Неоплаченный обязательный платёж, у которого день уже прошёл, показывается как просрочка, а не «через N дней» до следующего месяца
- Прогноз прошлого месяца считает средний темп за все дни этого месяца. Раньше вся сумма делилась на 1 день и умножалась на длину месяца
- В кассу из резерва возвращаются только проводки типа deposit. Строка с пустым или чужим типом больше не притворяется пополнением и не увеличивает кошелёк при снятии или удалении
